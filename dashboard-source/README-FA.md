# نسخه منبع داشبورد انبار و توزیع

این پوشه برای نگهداری نسخه قابل‌ردیابی فایل‌های رابط داشبورد در GitHub است. منبع اجرایی سرور همچنان همان برنامه فعلی است؛ این پروژه جایگزین API، پایگاه‌داده، احراز هویت یا سرویس ناوگان نیست.

## معماری و حفظ قابلیت‌ها

- رابط کاربری در \`public/dashboard/\` ذخیره می‌شود و فایل اصلی آن \`dashboard.html\` است.
- کد ناوگان و پرتال مدیریت ارسال در \`fleet.js\` قرار دارد.
- ورود، سطح دسترسی، اسناد، رسیدها، ارسال/بارگیری، مسیرها، اعلان‌ها و اطلاعات ناوگان به APIهای سرور فعلی متصل‌اند.
- برنامه از مسیرهای ریشه‌ای مانند \`/api/...\` و \`/dashboard/...\` استفاده می‌کند؛ بنابراین این فایل‌ها به‌تنهایی روی GitHub Pages اجرا نمی‌شوند. آن‌ها باید روی همان origin سرور فعلی سرو شوند.
- فایل \`data_export.txt\` عمداً در GitHub قرار نمی‌گیرد؛ ممکن است داده واقعی کسب‌وکار داشته باشد و روی سرور باید جداگانه نگهداری شود.

## همگام‌سازی منبع

Workflow موجود در \`.github/workflows/sync-dashboard-source.yml\` فقط فایل‌های مجازِ رابط کاربری را از نشانی عمومی داشبورد دریافت می‌کند. فایل پایگاه‌داده، \`.env\`، کلیدها، لاگ‌ها، اسناد و خروجی داده همگام نمی‌شوند.

## انتشار روی سرور

1. از کل پوشه فعلی \`C:\\Anbar-Server\\public\\dashboard\` بکاپ بگیرید.
2. نسخه GitHub را در یک پوشه محلی دریافت کنید.
3. PowerShell را با دسترسی مناسب اجرا و اسکریپت \`deploy-dashboard.ps1\` را اجرا کنید.
4. اسکریپت قبل از کپی از فایل‌های موجود نسخه پشتیبان می‌گیرد و فقط فایل‌های رابط کاربریِ مشخص‌شده را جایگزین می‌کند؛ فایل \`data_export.txt\`، \`server.mjs\`، \`worker.js\`، تنظیمات محرمانه و پایگاه‌داده تغییر نمی‌کنند.
5. ورود، نقش‌های کاربری، اسناد و رسیدها، داشبورد ارسال، نقشه و مسیر، پرتال راننده، اعلان‌ها و نصب PWA را دستی آزمایش کنید.

## نکته مهم

مخزن \`anbar-system\` عمومی است؛ بنابراین فقط کد رابط کاربری و وابستگی‌های لازم را در آن نگه دارید. این پوشه نباید شامل داده مشتری/فاکتور، پایگاه‌داده، رمز عبور، توکن یا کلید خصوصی باشد.
